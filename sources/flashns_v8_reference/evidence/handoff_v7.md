# FlashNS 迭代 RFC v7：从局部融合转向完整求解收益

日期：2026-09-09。状态：下一轮提案，v7 实验尚未执行。本文基于已经完成的 H100 NVL 实测与本地源码检查；所有优化目标、候选实现和收益预测均与已测结果分开。

## 1. 下一轮要解决的问题

当前的主要收益来自三阶空间导数的 jet 表示、原生前向与显式参数反传。B1 已经包含这些工作，所以相对 B1 的小幅提升不能被描述为整个项目只做了百分之一的优化；同样，相对嵌套 AD 的数倍提升，也不能全部归因于新融合或 TMA。

下一轮的主目标是：在同一 FP64 问题和停止标准下，相对开发阶段冻结的最快有效 jet 基线，降低完整求解 wall time。将 **1.10× 配对中位加速**作为研发目标，不作为已实现或保证能实现的结果。同时报告优化阶段耗时，避免把一次性 setup 改善描述成持续计算吞吐提升。

优先顺序：**耗时归因 → residual/loss/seed → 内点与边界计算拆分 → 有证据后优化前向或 wgrad → 完整求解复测**。TMA 保留现有已验证实现；没有新的瓶颈证据时，不继续扩大搬运配置搜索。

## 2. 已测基线与证据

### 2.1 完整求解

问题为二维 Kovasznay 稳态 NS，网络 2–64–64–3，4,547 个参数，2,048 个内点和 512 个边界点。GPU 为 H100 NVL，FP64、TF32 关闭。三个初始化种子相同，八个后端的数学目标、优化器及验收标准一致。

| 后端 | 优化与验收中位数 / s | 求解总计中位数 / s | 相对当前 Hopper TMA 的配对时间比 |
|---|---:|---:|---:|
| B1 | 21.848 | 22.528 | 1.014498× |
| cuBLASLt | 21.812 | 22.723 | 1.023283× |
| 既有融合 F | 21.867 | 22.427 | 1.009944× |
| Hopper TMA | 21.647 | 22.206 | 1.000000× |
| TorchJetCompiled | 21.472 | 25.941 | 1.168228× |
| CuEquivariance | 22.342 | 25.794 | 1.117091× |
| TorchNestedAD | 95.766 | 96.660 | 4.352906× |
| PhysicsNeMo | 117.541 | 118.790 | 5.278978× |

时间比先按同一初始化种子配对，再取中位数，因此不必等于两列耗时中位数之比。求解总计包含数据准备、后端 setup、Graph capture、优化器、线搜索、停止检查及独立验收；进程启动、导入和检查点写入另外记录。依赖及编译器缓存已由预检填充。

TorchJetCompiled 的优化阶段中位数略低于 TMA；TMA 对它的总时间优势包含 setup 差异。TMA 对 B1 的三个配对倍率为 1.014498、0.976816、1.074301，尚不能据三个种子将百分之一左右的差距认定为稳健优势。

首轮固定预算为 17/24 收敛。之后统一扩大 L-BFGS 上限，七次未收敛运行从相同初始化完整重跑，最终 24/24 达标，原失败记录保留。上表采用各组合达到验收的完整运行；实际执行包括失败尝试共 31 次，累计进程时间约 1,401.55 秒。

证据：[完整求解报告](flashns/docs/pinn-solver-results.md)、[统一追加预算协议](flashns/experiments/pinn_solver/artifacts/extension1/protocol.json)、[完整运行汇总](flashns/experiments/pinn_solver/artifacts/extension1/suite.json)、[汇总 JSON](flashns/artifacts/hopper_followup/solver-summary.json)。

## 3. 源码中已确认的优化入口

下表的“事实”来自代码；尚未取得它们各自的完整求解耗时占比。

| 入口 | 当前事实 | 待检验假设 |
|---|---|---|
| `manual_step` | 最终 jet 变为 autograd leaf，`jet_loss` 后调用 `torch.autograd.grad` 生成 seed | 显式融合 residual/loss/seed 可以减少中间物化和小算子 |
| `Problem` 与 `manual_step` | 内点和边界拼成 2,560 点，一起执行完整三阶 jet；边界 PDE 权重为零 | 边界只算函数值及参数梯度，可能减少无效高阶工作 |
| 前向 | 每层库 GEMM，随后独立 bias 与 stable tanh jet | 首层结构特化或前向 epilogue 融合可能有收益 |
| 参数梯度 | 每层独立 wgrad GEMM、bias reduction，最后 `torch.cat` | 若占比足够，布局或输出缓冲复用可能降低成本 |
| 求解控制 | 每 100 次 Adam、每个 L-BFGS block 验收；六指标转主机标量；线搜索使用公共 PyTorch L-BFGS | 主机同步与验收可能限制 kernel 收益，需单独归因 |

入口：[backends.py](flashns/experiments/pinn_solver/backends.py)、[problem.py](flashns/experiments/pinn_solver/problem.py)、[solve.py](flashns/experiments/pinn_solver/solve.py)、[residual 参考](flashns/experiments/cuda_jet_h100/common.py)。

## 4. 冻结的数学与精度合同

- 保持 FP64、完整 Taylor 三阶基、阶乘归一化、stable aux 数值策略。二维 Q=10，三维 Q=20；首轮新求解优化仅针对二维，已有三维接口保留原实现。
- 保持物理坐标、ν=0.07、网络、训练点、权重、边界条件与初值生成规则。主基准使用既有 2,560 点问题。
- loss 保持 `0.5 * mean_interior(ru² + rv² + div² + 0.2*(|grad ru|² + |grad rv|² + |grad div|²)) + 5*(mean_boundary(|uv-uv_exact|²) + mean_outflow((p-p_exact)²))`。
- 不能在拆分边界时重新按子批量归一化，也不能增加 `/Q`。u/v 边界与压力出流边界使用各自既定权重。
- 保持 Adam 4,000 步及既有学习率表；L-BFGS 从已公开的统一 500 blocks 上限开始，保留原 strong-Wolfe 和容差。先传入冻结协议，不能误用 `solve.py` 默认的旧 200 blocks 上限。
- 停止检查位置不变；保留独立第二组 scalar AD 验收。六阈值依次为 PDE RMS 0.02、边界 uv RMS 0.01、出流压力 RMS 0.01、相对 L2 的 u/v/p 为 0.01/0.02/0.02。
- 当前 native 接口只承诺一阶参数 VJP。HVP、double backward、C8/C13 压缩、混合精度及修改优化器属于另一组实验。

## 5. P0：先建立完整耗时账本

对 B1、旧 F、TMA、TorchJetCompiled 至少各做一次独立归因，并保留未插桩计时。覆盖实际求解 2,560 点和局部梯度 4,096 / 16,384 / 65,536 点；初始化、Adam 中段和 L-BFGS 使用的参数状态分别采样。

记录以下互不混淆的边界：

1. 数据准备、依赖/编译器缓存状态、后端 setup 和 Graph capture。
2. 前向 affine、bias/activation、residual/loss/seed、各层 wgrad、dgrad/VJP、bias reduction 和梯度拼接。
3. Adam 更新、L-BFGS 的目标评估次数与主机控制、周期验收和最终独立验收。
4. 未插桩完整 gradient replay、优化阶段 wall、求解总 wall、进程总 wall；各边界有明确定义。

使用 CUDA events、同步 wall 和当前允许取得的 trace。插桩和拆开的阶段可能改变执行，阶段和不能代替未插桩总时间；允许的时间轴若有重叠，按区间并集解释。硬件计数器仍不可用时，记录限制，继续开展可观测的归因。

选择下一项实验前，用相同计时边界估计 Amdahl 上限：若可优化部分占比为 p、局部加速为 s，则整体预计倍率为 `1 / ((1-p) + p/s)`。例如 p=10% 即使局部快一倍，整体也只有约 1.053×；这是公式示例，不是已测占比。

交付：阶段时间表、调用次数、独立 trace、未插桩对照、明确到源码入口的优先级。没有这些证据，不扩大新的 TMA/stage/warp 配置搜索。

## 6. P1：residual/loss/seed 的显式实现

候选输入为输出 jet `[B,10,3]`、PDE 权重、边界权重和目标函数值；输出为标量 loss 与完整同形 seed。每个样本的局部计算可独立处理，loss 的全局归约单独明确所有权。

实施步骤：

1. 从当前固定目标建立独立 CPU/符号表达式，写清每个 jet 分量对应的阶乘恢复和 seed 的转置映射。
2. 保留现有 eager/Graph autograd 路径，并增加编译张量版 residual/seed 作为强对照；已有 TorchJetCompiled 只替换激活实现，不等于整个 residual/seed 已编译。
3. 再实现有限特化 CUDA 候选；采用可解释的分块归约，保留 FP64。避免把不稳定的原子累加顺序默认为可逐值重放。
4. 验证任意合法 jet、非均匀/零权重、边界点、混合导数和饱和尾部；随后验证全部参数梯度与实际 Adam 更新。
5. 对残差阶段、完整梯度和完整求解分别计量，测试原参数地址在 Graph replay 中真实更新。

单独消融：原生 baseline；仅编译 residual/seed；仅显式 CUDA residual/seed。其他 GEMM、activation、优化器及检查规则保持一致。若完整梯度改善不足 3% 且没有可验证的内存收益，不继续扩大该候选的模板范围。

## 7. P2：内点高阶 jet 与边界函数值拆分

当前 512 个边界点占训练点的 20%，边界 loss 只依赖 u/v/p 的函数值。候选将 2,048 内点沿完整 jet 路径计算，将 512 边界点沿普通 FP64 MLP 前向与一阶参数反传计算；两部分使用同一组参数，按原权重相加 loss 与参数梯度。

从矩阵行数计算，隐藏层相应工作可由 `2560*10=25600` 行变为 `2048*10+512=20992` 行，减少 18%。这是部分矩阵工作的行数推导，不是完整步骤或求解省时预测；拆成更多 GEMM、梯度合并和额外 launch 都可能抵消收益。

必须保持两条路径的 stable tanh 语义，边界普通反传也使用稳定导数因子，不能在饱和区直接退回会丢失极小导数的 `1-tanh(z)^2`。原始权重、参数视图及所有边界重复采样点必须完整保留。

先比较“仅拆分边界”与原路径，再做 P1/P2 四组消融：原版、仅 P1、仅 P2、P1+P2。通用拆分若也能用于 B1/编译版 jet，应给它们同等适配，重新区分通用工作量减少与自研内核的额外收益。

验收包含训练点重排、空边界/空内点的小型实现检查、分量权重、loss、全参数梯度以及实际更新。正式性能仍使用冻结的完整问题。若额外调用使主基准回退，保留反例，不默认启用。

## 8. P3：依据 P0 决定前向或 wgrad 实验

只选择一个被测成本足够大的方向，再进行单项对照：

- 首层输入是坐标 seed，高阶输入为零，一阶输入固定；可试首层 affine 与 stable jet 生成的结构特化，保留数学输出与参数 VJP。
- 若中间层前向占比更大，可试 GEMM 输出到 bias/stable activation 的融合；不要假定 dgrad 的最优 layout 同样适用。
- 若 wgrad 或 reduction 占比突出，先检查 transpose、布局、输出缓冲与库计划，再考虑自定义归约；同时测 workspace 和数值误差。
- 若主机控制/验收占主导，先优化同一控制语义下的状态搬运和执行方式。减少验收频率或替换 L-BFGS 会改变实验合同，另立协议。

完整梯度改善不足 3% 且无明确内存收益时停止扩展该方向。全网 persistent、warp specialization、HVP、压缩 jet 和多卡迁移不作为本轮的默认前置任务。

## 9. 性能协议与继续条件

### 9.1 基线选择

保留 B1、cuBLASLt、F、TMA、TorchJetCompiled 和 CuEquivariance 六条有效 jet 路径。开发集合中选择主对照并冻结它的版本、设置与选择规则；完整求解总时间和热优化时间可能各有不同最优基线，两个指标分别注明比较对象。

通用优化必须同时提供给适用的强基线。不得只给候选使用 Graph、预热、缓存、边界拆分或相同的 loss 简化。不得在最终测量后逐轮挑最快基线或只挑候选获胜尺寸。

### 9.2 筛选与确认分离

- 开发 pilot 使用 361901 / 361902；旧 75101/75102/75103 用于回归，不作为新增独立样本。
- 建议正式新增初始化种子为 75201–75210，执行前写入独立协议。候选冻结后才使用这组种子。
- 完整梯度每个尺寸至少 15 轮随机交错配对，记录每轮事件与 wall time、输入哈希、状态及 setup。2,560 点是必测尺寸。
- 完整求解对每个新种子分别运行主基线和最终候选，使用新参数、优化器和 Graph，保持缓存政策一致；保存全部观测而非只存中位数。
- 以同种子 `T_baseline/T_candidate` 为统计单位，报告中位数、逐种子散点和固定种子的配对 bootstrap 区间。样本范围仅覆盖该固定问题与设备，不作普遍性能结论。

### 9.3 升级条件

目标为求解总时间配对中位倍率至少 1.10×，95% bootstrap 下界高于 1.0；优化阶段不得出现超过 2% 的中位回退。这些阈值是本轮预设研发判断，不是科学定理。

主基线和候选在十个种子上都须达到原六阈值及独立 AD 验收。未达标运行保留失败状态与已花费时间，不把失败样本剔除后宣称完整求解获胜。若再次调整统一迭代上限，另存协议和完整重跑结果，并报告累计成本。

正确性要求至少继承现有 `2e-12 + 2e-11*abs(reference)` 的完整 loss/梯度/更新检查及相应的高精度局部诊断。由于有限精度会影响 L-BFGS 轨迹，不要求跨后端逐步参数完全相同；必须验证数学目标、数据和最终质量一致，单独记录轨迹差异。PhysicsNeMo 已有跨进程轨迹分离记录，不能声称它逐值可重放。

新增 CUDA 路径通过 memcheck、racecheck、initcheck、synccheck，覆盖尾块、非默认 stream、Graph 参数更新与回退入口。硬件、编译版本、源码/二进制哈希随报告保存。

## 10. 官方构造与其他工作负载

OpenAI 官方构造已经完成固定版本 CPU 构建、两个 Comparator 挑战的四声明双 kernel 检查，以及局部波幅方程数值适配。局部算子含传输加速为 5.743–10.865×；驻留 GPU 的更大倍率不代表完整构造、轨迹积分或证明检查的加速。

当前 Kovasznay 求解、官方构造局部波幅与 Euler 冻结样条使用各自 source_id。下一轮若扩展官方构造，应先定义新增有限对象及独立参考；不把当前 PINN 的结果记为官方整体构造的数值实现。正式证明工具链无变化时，无需为每个 PINN kernel 实验重复完整构建。
