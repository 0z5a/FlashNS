# H20 二维实验的 H100 补测

本批次复用原 H20 二维 Kovasznay 的 460 个源码文件、物理损失、`2–64–64–3` 网络、2,048 个内部点和 512 个边界坐标。MN5 已核对原始 5 个数据/权重哈希及 6 组初始化哈希；全部一致。训练仍使用原 4,000 次 Adam、最多 500 块 L-BFGS 和原 6 项精度条件，包括独立标量坐标 AD 验收。

代码将原始 H20 科学程序作为冻结输入，补上 H100 调度、原始参数字节加载、完整梯度数组保留与独立验收。cuEquivariance polynomial 沿用 H20 已记录的初始化修复，仅省略其未使用的 FlashNS 原生库初始化；其数值方法不变。不会改写原科学源码、放宽阈值或延长训练预算。

单节点 4 张 H100 的有限清单分为四条独立队列，合计 23 个 GPU 资格案例、78 次正式求解、30 个显存/重放案例。公开论文组、NVIDIA 组、表示求解组和显存组分别运行；NVIDIA 组另有 6 次 GL8 求解提供同卡对照。每个时间比值使用同一物理 GPU、同一初始化且双方均通过验收的配对。资格阶段保留失败变体，并按通过变体的开发重放中位数选择执行模式；不按正式收敛结果选择。

运行环境在 GPU 分配前准备。核心库为原 H20 的 Torch 2.12.1+cu130、Triton 3.7.1、NumPy 2.4.6、SciPy 1.18.1 和 JAX 0.11.2。大部分 CUDA/Torch wheel 已在 MN5 内部复用。原 H20 后装依赖的 53 个包按其原安装 SHA256 核验。7 项实际 CPU 基线检查已通过三次参数更新，原生 CUDA 内核已在 CPU 上成功构建；这些均不等于 GPU 验收。

测试使用现有集群工具链，实际驱动、CUDA 编译器与 CPU/GPU 绑定都会记录。软件/编译器差异与原 H20 分开披露，不把跨设备差异直接归因于硬件。

`h20_node.py` 在分配启动时自动执行，创建并保留原始 GPU 锁，派发每条队列的独立子进程，等待真实退出，执行 `audit_h20.py`，完整归档并逐成员校验。失败时也保存原输出并关闭所拥有的子进程。安装环境及 wheel 是持续保留的输入，归档保存科学输出、源码、检查点、日志与生成缓存。Mac 或 SSH 断开不影响工作和资源释放。

`audit_h20.py` 使用 NumPy 重读资格阶段的完整 4,547 参数梯度及计时数组；对每个已通过的最终训练检查点，额外执行完整 CPU 标量坐标 AD 验收。失败及未运行项保留在总表中。批次完成后自动输出 `chinese-summary.zh-CN.md`，包含实际合格配对数量、加速比和全部尝试的结果计数。Slurm 完成或脚本退出 0 不是性能通过的替代条件。

当前 GPU 结果待执行与独立核验。此前 H100 三维 C36 的 1.324× 是另一问题的目标/梯度吞吐结果，见 [中文思路摘要](../manuscript/flashns-summary.zh-CN.md)；它不会被充作本次二维求解数据。
